1. Overview

Application

FMView is a Windows application designed to simplify the review and interaction with various components of the Veterans Health Information Systems and Technology Architecture (VistA). With FMView, users can:

  • View the definitions and contents of FileMan files, including data dictionaries, file attributes, and data entries.
  • View M routines.
  • View VistA globals.
  • Execute and review the implementation of remote procedures.

FMView requires the XWB and FMDC packages to be installed on the server, as well as a custom RPC (remote procedure call) to access file definitions and routine source code on VistA accounts. This application is designed to work with Caché and GT.M environments and to connect to VistA instances that use the hash tables VistA, VistA Demo, and OSHERA.

Disclaimer
⚠ Important — Data Safety This application enables users to view and modify data on both server and client machines. It is not intended to be a VistA data-editing tool, and improper use may cause data corruption or loss. Test the application on a non-production database instance first and verify compatibility with your server software version before accessing any critical data.

This application is provided "AS IS" WITH NO WARRANTIES. The author is not responsible for any data loss or damage that may occur as a result of using this application.

Privacy Policy

The application does not collect any personal information from the user. It may create a log file that records connections to VistA accounts and RPC executions. This log file is stored on the local machine where the application is running.

By default, configuration information is saved in the user's AppData\Roaming\FMView folder.

Implementation

FMView v.2.0 is built with Embarcadero Delphi 12 (Community Edition). VistA file data is accessed through the FileMan Delphi Components (FMDC v1.0) library. Information about VistA component definitions — file definitions, routine source code, and global contents — is provided by a custom RPC. Communication with VistA servers is handled by a customized version of VistA Broker. The SynEdit and VirtualTree (TurboPack) packages are used for routine syntax highlighting and data presentation.

2. Quick Start

Installation
  1. Place the application executable in a folder to which you have write access.
  2. Create a desktop shortcut if you need to pass custom startup parameters.
  3. Register the custom RPC (ZZFMVIEW) on each target VistA account before connecting.
ℹ Note The application does not require a formal installer. The executable is self-contained, and the configuration file is created automatically on first run.
First Start

Start the application by clicking its executable or shortcut in Windows Explorer.

At startup, the application loads data from the configuration file, which stores connection parameters, open window descriptions, user comments, interface preferences, and more.

The very first time the application is launched, no configuration file exists, and the user is prompted to enter VistA connection parameters in the VistA Account List dialog.

Creating a Connection Record

  1. Click the New button.
  2. Fill in the connection record fields, replacing the default values:
    • Caption — A descriptive name for this connection record.
    • Server — The IP address or hostname of the VistA server.
    • Port — The port number used by the VistA Broker service.
    • Access;Verify Codes — The user's Access and Verify codes, separated by a semicolon (;).
    • RPC Name — The name of the custom RPC (ZZFMVIEW by default).
    • Application Context — The context in which the RPC is registered.
    • Hash — The selected hash table.
  3. Click OK to save the record and close the dialog.

You can create multiple connection records for different VistA servers and switch between them using the drop-down list on the main toolbar. When finished adding records, click OK.

Connecting to a Server

  1. Select a connection record from the drop-down list on the main toolbar.
  2. Click the Connect button.
  3. Check the status bar for the connection result.

If the connection is successful, the toolbar buttons become active:

If the Connection Fails

A warning message is displayed and the toolbar buttons are disabled:

Click the Connect button to review the connection parameters and try again.

Start comparing routines by clicking the button (located at the right end of the toolbar).

13. Configuration and Preferences

Configuration File

The configuration file stores connection parameters, open window descriptions, user comments, interface preferences, and more. By default it is located at:

%APPDATA%\Roaming\FMView\

To specify an alternative location, use the /config startup parameter:

/config=MyConfig.cfg
Master Password

The configuration file may contain Access/Verify codes stored in encrypted format. Encryption and decryption use the master password. If no password is provided, a default decryption method is applied.

⚠ Warning There is no password validation. If the wrong password is entered, the decrypted Access/Verify codes will not work and connections will fail without an explicit error message.

Use the Enter Master Password dialog to set the password:

⚠ Security Note Supplying the master password as a startup parameter (/MPASS=) is possible but not recommended, as it may be visible in system process listings or shortcut properties.

Autosave protects your work by periodically saving the application configuration without user interaction. The autosave interval is specified in minutes. A save is triggered when no keyboard input or mouse clicks have been detected for the full interval.

  1. Open the Preferences dialog.
  2. Click the Autosave Interval button:
  3. Enter the interval value in minutes and confirm:

The default interval is 30 minutes.

Startup Parameters

The following parameters can be passed to the application executable, for example via a shortcut's Target field:

ParameterDescriptionExample
/config= Specifies an alternative path for the configuration file. /config=C:\MyConfig.cfg
/MPASS= Supplies the master password at startup. Not recommended — the value may be visible in process listings or shortcut properties. /MPASS=MySecretPass
/NOPASSWORD Forces use of the default decryption without prompting for a master password. /NOPASSWORD
/GW Enables saving changes to routine source code back to VistA. Without this switch, the Save As button in the Routine viewer is inactive. /GW
⚠ Write Access Warning The /GW switch grants the ability to overwrite routine source code on the VistA server. Use it only on non-production accounts unless you are intentionally making server-side changes.

Properties
        .01      Name                      ZZFMVIEW
        .02      Tag                       RPC
        .03      Routine                   VWFMVIEW
        .04      Return Type               ARRAY
        .05      Availability              PUBLIC

Parameters Definition
        #    Name         Type         Length       Required
        ----------------------------------------------------

        2    ARRAY        LIST         32000        NO

15. Glossary

A/V Codes (Access/Verify Codes)
The two-part credentials used to authenticate a user on a VistA system. The Access code identifies the user; the Verify code is the password.
Caché
An object database management system by InterSystems, one of the supported runtime environments for VistA.
DD (Data Dictionary)
The FileMan structure that defines the metadata for a VistA file: its fields, cross-references, identifiers, and other attributes.
DIC
The global (^DIC) that serves as the FileMan index of all files registered in a VistA account.
FileMan
The database management system built into VistA. FileMan stores all clinical and administrative data in a hierarchical structure of files and fields.
FMDC (FileMan Delphi Components)
A Delphi component library that provides programmatic access to FileMan data, used internally by FMView.
Global
A persistent, hierarchically addressed variable stored in the VistA database. Globals are the underlying storage mechanism for all FileMan data.
GT.M
An open-source M (MUMPS) runtime and database engine, one of the supported environments for VistA.
Hash table
A namespace identifier used to select the target VistA instance when connecting through VistA Broker. Common values are VistA, VistA Demo, and OSHERA.
M (MUMPS)
The programming language in which VistA applications and routines are written.
RPC (Remote Procedure Call)
A registered server-side routine that can be invoked by a client application over the network through VistA Broker.
Routine
A named M program stored on the VistA server. Routines implement application logic and are identified by their name in the ^ROUTINE global.
VistA
Veterans Health Information Systems and Technology Architecture — the electronic health record and hospital information system used by the U.S. Department of Veterans Affairs.
VistA Broker (XWB)
The client-server communication layer for VistA. It allows desktop applications to call RPCs on a remote VistA server over TCP/IP.
VIVIAN
A public VistA reference source accessible through the comparison feature, allowing local routines to be compared against a known baseline.
XWB
See VistA Broker.
